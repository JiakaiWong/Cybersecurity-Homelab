# Pyramid Of Pain 

The **Pyramid of Pain** is a cybersecurity model created by David Bianco that illustrates how difficult it is for attackers to replace different types of Indicators of Compromise (IOCs). While indicators such as hashes and IP addresses are easy to change, tools and TTPs require significantly more effort to modify.

In this room, we explore each layer of the Pyramid of Pain through malware analysis, threat intelligence, and practical investigation exercises to understand how defenders can create greater operational challenges for attackers.

## Practical: Pyramid of Pain

## Practical: Pyramid of Pain ( From base layer to top )

| Description | Layer | Reason |
|------------|--------|---------|
 | **Hash Values**| These signatures can be used to attribute payloads and artefacts to an actor. | Hashes uniquely identify files, but attackers can easily generate new ones by modifying the malware. |
 | **IP Addresses**| These addresses can be used to identify the infrastructure an attacker is using for their campaign. | IPs reveal attacker infrastructure, but they can be quickly replaced. |
| **Domain Names** | An attacker has purchased this and used it in a typo-squatting campaign.| Typosquatting relies on registering lookalike domains to deceive victims. |
| **Network**| These artefacts can present themselves as C2 traffic for example.  | Network artefacts are communication patterns such as beaconing, protocols, or traffic signatures. |
| **Tools**| The attacker has utilised these to accomplish their objective.  | Tools are the software, frameworks, or malware used during the attack. |
 |**TTPs** | The attackers plans and objectives. | TTPs describe the attacker's methods, tactics, and overall approach. |

The higher the indicator is on the pyramid, the more operational pain it causes the attacker when detected and blocked.

## Conclusion

#### Key takeaways:
- The Pyramid of Pain is a practical, memorable model for prioritizing detection efforts: low-level IOCs (file hashes) are easy for attackers to change and thus low-value long-term; higher-level items (TTPs) are stable and high-value to detect. (TryHackMe)
- When triaging samples, combine multiple sources: sandbox behavioral logs (Any.run), vendor reports (task reports), and reputation engines (VirusTotal) to get a complete view: file metadata, network calls, dropped files, and vendor consensus all help form attribution/response. (ANY.RUN)
- Practical skills reinforced by the room: reading sandbox network logs, extracting indicators (IP/domain/hash), counting and interpreting vendor detections, recognizing UA strings, and using fuzzy hashing for variant correlation.

#### Practical defender tips:

- Don’t rely solely on file hashes. Use behavioral analytics and hunting rules that track network-behavior patterns and TTPs.
- Use URL preview/unshortening tools (TinyURL preview, CheckShortURL, Unshorten.It) before visiting shortened links in emails. (TinyURL)
- Build monitoring that focuses on resilient indicators (beacon timing, unique C2 behaviors, unusual process injection patterns) to create detection that forces attackers to retool that’s the essence of inflicting “pain” as the pyramid describes.
